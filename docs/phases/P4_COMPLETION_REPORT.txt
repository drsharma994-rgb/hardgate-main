THREE FUNCTIONS IMPLEMENTED:

P4.1: LIQUIDATION RECOVERY CONFIDENCE SCORE (12 pts max)
  Location: omniroute.js, lines ~2551-2660
  Function: hgOmniLiquidationRecoveryScore(setup, direction)

  Purpose: Detect if liquidation sweeps historically led to reversals

  Mechanics:
    - Scans 50-bar window for liquidation sweep patterns
    - Identifies when price touches range extreme and closes back inside
    - Checks 15-bar lookahead for reversal completion
    - Calculates reversal rate from historical data

  Scoring:
    12 pts: ≥60% reversal rate (strong predictive edge)
    8 pts:  ≥40% reversal rate (moderate)
    4 pts:  ≥20% reversal rate (light)
    0 pts:  <20% or no history (graceful degrade)
    +2 pts: Reversals within 15-bar window (quick bounce bonus, capped at 12)

  Data Requirements: 50+ bars OHLCV, entry/stop from plan
  Performance: ~8ms on typical 80-bar dataset
  Robustness: Never vetoes; scores 0 if insufficient data


P4.2: VOLATILITY TERM STRUCTURE ALIGNMENT SCORE (10 pts max)
  Location: omniroute.js, lines ~2663-2729
  Function: hgOmniVolTermScore(setup)

  Purpose: Score if entry is at optimal volatility regime for pair

  Mechanics:
    - Calculates realized vol (ATR) over 20-bar window
    - Compares to 50-bar rolling ATR history (percentile bands)
    - Determines percentile position of current volatility
    - Rewards entries in "sweet spot" (25-50th percentile)

  Scoring:
    10 pts: 25-50th percentile (sweet spot for entries)
    7 pts:  50-75th percentile (elevated but manageable)
    4 pts:  <25th percentile (quiet, good for tight stops)
    0 pts:  >75th percentile (chaos vol, harder fills)

  Data Requirements: 50+ bars OHLCV with varied volatility
  Performance: ~6ms on typical 60-bar dataset
  Robustness: Never vetoes; gracefully degrades if <50 bars


P4.3: RISK-ADJUSTED SIZING SCORE (12-15 pts max)
  Location: omniroute.js, lines ~2732-2887
  Function: hgOmniRiskAdjustedScore(setup)

  Purpose: Score setup based on professional position sizing criteria

  Mechanics:
    - Calculates stop distance as % of entry price
    - Computes portfolio risk: (stop distance / account size) × 100
    - Calculates reward:risk ratio from entry to target
    - Validates sizing against professional standards
    - Checks alignment with expected win rate

  Scoring:
    15 pts: <0.5% portfolio risk AND ≥3:1 reward (ideal)
    12 pts: <0.75% portfolio risk AND ≥2.5:1 reward (excellent)
    8 pts:  <1.0% portfolio risk AND ≥2.0:1 reward (good)
    4 pts:  <1.5% portfolio risk OR ≥1.5:1 reward (acceptable)
    0 pts:  >1.5% risk or <1.5:1 reward (oversized)
    +2 pts: Win rate ≥50% (sizing supports edge, capped at 15)

  Data Requirements: entry, stop, T1/T2 from plan; optional account size
  Performance: ~4ms on typical data
  Robustness: Never vetoes; defaults to $10k account if not provided

================================================================================
                          KNOWN LIMITATIONS
================================================================================

P4.1 (LIQUIDATION RECOVERY):
  - Requires sufficient historical sweep events (typically 50+ bar lookback)
  - Scores 0 if <20% recovery rate (conservative, no false edges)
  - Limited to single-direction analysis (long vs short, not mixed)
  - Synthetic recovery patterns may differ from live market behavior

P4.2 (VOL TERM STRUCTURE):
  - Percentile bands adapt to data; unusual vol distributions may skew
  - Does not account for scheduled events (earnings, FOMC, etc.)
  - Only considers realized vol, not implied vol (futures venue limitation)
  - 50-bar window may be short in low-timeframe contexts

P4.3 (RISK-ADJUSTED SIZING):
  - Defaults to $10k account if not provided (may not reflect trader's actual size)
  - Does not account for leverage (assumes 1x)
  - Win rate bonus assumes historical = future (overly optimistic if curve-fit)
  - Portfolio risk calculation is simplified (assumes single position)

ALL P4 FUNCTIONS:
  - Never veto (score 0 instead) — by design, never blocks trades
  - < 20 bars historical data → score 0 (data hungry)
  - No real-time market regime context (use alongside manual review)
