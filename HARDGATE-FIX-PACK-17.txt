HOW THE PORT REWRITE ACTUALLY WORKS
-----------------------------------
index.html:55-75 already has the shim:

    var RAW = '__PORT_8420__';
    if (RAW.indexOf('__PORT_') === 0) return;  /* local dev, no-op */
    var PREFIX = '/' + RAW.replace(/^\/+/, '');
    window.fetch = function(input, init){
       ...if input starts with '/api/' → prepend PREFIX...
    };

deploy_website / publish_website scans the bundle for __PORT_8420__ and
rewrites it to 'port/8420' (the exact ingress path pplx.app uses to reach
the sandbox on that port).  From then on every '/api/...' fetch is
transparently rerouted to '/port/8420/api/...'.

On Render (scripts/server.mjs) the placeholder stays literal → the shim
no-ops → same-origin '/api/...' hits the real server directly.

To PUBLISH the site with the backend, use the run_command flag:

    publish_website(
      project_path="/home/user/workspace/hardgateperplexity",
      dist_path=  "/home/user/workspace/hardgateperplexity",
      run_command="node scripts/server-minimal.mjs",
      port=8420,
      app_name="HARDGATE",
      site_id="40ad8986-2b52-407f-abae-5348d5191b8c"
    )

The site_id keeps the same slug (hardgateperplexity1.pplx.app) and the
same publish record — no new URL, no stale twin.

KNOWN LIMITS / CHOICES I MADE FOR YOU
-------------------------------------
- The pplx.app sandbox is single-instance and can be recycled.  If you
  see /api/coindcx/* going 404 again after a long idle, the server may
  have been evicted — republish (same command, same site_id) and it
  comes back on the same URL.
- Delta India works direct because it sends Access-Control-Allow-Origin:*.
  If Delta ever tightens that, we'd need to add the Delta paths to
  server-minimal.mjs too — trivial one-liner in the router.
- I did NOT mount /api/book, /api/execute, or the XM trader routes.
  They are execution paths, and the app is signal-only.  Anything that
  tries to hit them on pplx.app will 404, which is the correct behaviour
  for a public URL.
- Render is unchanged.  scripts/server.mjs is still the production entry
  and mounts the full API surface.  server-minimal.mjs is a pplx.app-only
  companion.
